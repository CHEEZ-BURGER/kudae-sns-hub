# 고대신문 SNS Upload Helper 2.3.7

2.3.7은 X 자체 글 작성 링크로 제목·기사 링크를 미리 채운 새 탭을 연 뒤, 이미지 전용 댓글을 준비합니다. 자동 타이핑·붙여넣기·편집기 DOM 덮어쓰기로 X 글을 입력하지 않습니다. 먼저 현재 X 작성창에 글이나 사진이 없는지 확인하며, 기존 초안은 지우거나 이동하지 않습니다. X가 채운 제목·빈 줄·기사 URL이 원고와 일치하는지 확인한 뒤 원본을 한 번만 가져옵니다. 최종 게시·예약·초안 저장은 직접 해야 합니다. 추가 권한이나 유료 API는 사용하지 않습니다.

2026-10-08 로컬 점검 페이지의 정상 앱 연결 → 설치된 2.3.7 백그라운드 → 실제 X 경로에서 2050호 배포의 원본 PNG 6장으로 확인했습니다. 첫 글에는 분류 포함 제목·기사 링크만 한 번, 댓글에는 원본 4장·2장과 빈 텍스트가 유지됐으며 모든 사진은 1500×2000 원본 크기였습니다. 완료 이벤트도 6개 전달을 확인했습니다. 이어서 로컬 웹 배포 페이지의 실제 X 버튼으로 링크 없는 첫 기사 원본 8장(4+4)을 확인했고, 웹이 1/4에서 2/4로 자동 이동하는 것도 확인했습니다. 게시·예약·초안 저장은 누르지 않았고 검증용 임시 초안만 폐기했습니다. 단위/회귀 테스트 171개와 최종 전체 빌드가 통과했습니다. 확장 패널 버튼의 실제 UX와 공개 배포 후 점검은 별도 검증 범위입니다. 공개 배포는 별도 승인 전까지 하지 않습니다.

새 글은 빈 홈 작성칸이나 빈 새 글 작성창에서 시작할 수 있습니다. X 홈의 `Add post` 링크로 글을 옮기지 않습니다. 답글·인용창에서는 새 탭을 열거나 제목·링크를 덧붙이지 않고 원본 최대 4장만 넣습니다. 4장 초과는 일부도 넣지 않고 새 글 스레드에서 진행하도록 안내합니다. 확장과 X 탭을 모두 새로고침해야 합니다.

X/페이스북/고파스/에타/YouTube 탭을 오래 열어둬 확장 연결이 끊겼다면 다음 요청에서 연결만 복구합니다. 원본이나 글을 반복 입력하는 방식의 복구가 아닙니다. 전송 도중 연결을 잃으면 초안을 보존하고 작업을 실패로 종료합니다. 이미 들어간 첨부를 자동 재전송하거나 다음 기사로 이동하지 않습니다.

부장이 공유한 고대신문 SNS 배포 링크를 Chrome 오른쪽 패널에서 열고, 글 이동·제목/본문 복사·이미지 순차 복사·원본 파일 전달을 한 화면에서 처리하는 무료 사내용 확장입니다.

## 설치 또는 1.x에서 업데이트

1. 배포실에서 `Chrome 확장 다운로드`를 눌러 최신 ZIP을 받습니다.
2. ZIP을 별도 폴더에 압축 해제합니다.
3. Chrome 주소창에서 `chrome://extensions`를 엽니다.
4. 기존 확장을 업데이트할 때는 최신 ZIP의 내용을 기존 설치 폴더에 덮어쓴 뒤 확장 관리 화면에서 해당 확장을 새로고침합니다. 새 폴더에 설치한다면 기존 확장과 중복되지 않게 해 주세요.
5. 우측 상단 `개발자 모드` → `압축해제된 확장 프로그램을 로드합니다` → 압축을 푼 폴더 중 `manifest.json`이 보이는 폴더를 선택합니다.
6. 확장 아이콘을 눌러 오른쪽에 `고대신문 배포 패널`이 열리는지 확인합니다.

Chrome 148 이상 PC에서만 동작합니다. Android/iPhone Chrome은 확장 프로그램을 지원하지 않으므로 모바일 기자는 기존 배포 링크의 순차 복사·원본 저장을 사용합니다.

## 사용

1. Chrome 도구 모음의 고대신문 확장 아이콘을 눌러 오른쪽 패널을 엽니다.
2. 부장이 카카오톡으로 준 배포 링크 전체를 붙여 넣고 `불러오기`를 누릅니다. 기존 `#/d/...` 주소와 새 `share/2045-thu.html#/d/...` 미리보기 주소를 모두 지원합니다. 배포 페이지에서 `배포 패널 열기`를 눌러도 링크가 자동 입력됩니다.
3. 하단 고정 `이전 글`·`다음 글`로 게시물을 고릅니다. 수동 제목·본문 복사도 계속 사용할 수 있습니다. 본문 끝은 기사 안내문 → 기사 링크 → 크레딧 순서입니다.
4. Chrome 본문 탭에서 Facebook, 고파스, Instagram, YouTube/YouTube Studio, X, 에타 중 업로드할 곳을 엽니다. 패널의 초록 점이 해당 사이트를 감지합니다.
5. SNS의 새 글 작성창을 연 뒤 `현재 SNS에 이미지 + 글 넣기`를 누릅니다. 고파스·에타·YouTube Studio 전용 버튼은 열려 있는 해당 탭을 찾아 제목과 본문/설명을 각각 넣습니다. 나머지는 분류 포함 제목 → 두 줄 띄우기 → 본문·링크·크레딧을 한 칸에 넣습니다.
6. 내용과 이미지 순서·비율을 확인하고 최종 게시 버튼은 직접 누릅니다.
7. 원본 수량과 글 입력 성공을 확인하면 배포 패널/배포 페이지가 **다음 글로 자동 이동**합니다. 마지막 글에서는 멈춥니다. SNS에서 실제 게시했는지 기록하거나 게시 버튼을 자동으로 누르는 기능은 아닙니다.
8. 사이트 화면 변경, 글자 수 제한, 기존 작성 중인 글, 취소/입력 실패 때는 현재 글을 유지합니다. 일부만 전달하고 완료로 처리하지 않습니다. 수동 복사와 원본 다운로드를 계속 사용할 수 있습니다.

2.3.2는 불필요한 시작 박스·STEP·중복 안내를 제거하고, 썸네일 선택 테두리를 안쪽으로 옮겼습니다. 주 입력 버튼은 아이콘 없이 최소 74px로 확대했으며, 전달 단계는 원본·글·작성창 아이콘으로 보여 줍니다. 이미지 입력 시 기존 썸네일을 숨겨 빈자리를 유지하며 이미 표시된 이미지의 캔버스 사본이 날아갑니다. 검증된 완료 후 다음 글로 이동하면 비행 종료 뒤 새 썸네일만 차례로 튀어나옵니다. 패널 전체의 꿀렁 모션은 없습니다. 실패·취소 시 현재 썸네일을 복구합니다. 추가 원본 요청이나 파일 저장 없이 재생하며, 모션 감소 설정을 존중합니다. 모션이 실제 전송 성공이나 게시물 이동을 결정하지 않습니다.

2.3.1의 페이스북 수정도 유지합니다. 사진·영상 미리보기를 먼저 확인하고, 본문은 편집기의 붙여넣기 경로로 한 번만 입력합니다. 모든 원고 문자를 텍스트로 처리하며 줄바꿈만 안전한 BR 요소로 표현합니다. 미리보기를 확인하지 못하면 완료나 다음 글 이동으로 처리하지 않습니다. 작성 중인 다른 글은 덮어쓰지 않습니다.

최신 ZIP을 같은 기존 폴더에 교체한 뒤 `chrome://extensions`에서 확장을 새로고침하고, 배포 페이지와 열려 있는 SNS 탭도 새로고침해 주세요. 예전 연결 코드가 남아 있으면 패널 전체에 새로고침 안내가 표시됩니다. 추가 권한은 요청하지 않습니다. 실제 페이스북 계정의 작성창에서도 이미지 수·본문·줄바꿈을 확인한 뒤 직접 게시해 주세요.

2.3.3은 에타의 배경 이미지 썸네일과 파일 선택칸 초기화를 인식하고, 첨부 실패 안내에서 이미 입력된 글과 아직 넣지 않은 글을 구분합니다. Facebook은 작성창의 지연 로딩과 모달/전체 페이지 형식을 처리합니다. YouTube 커뮤니티 게시물은 이미지 모드를 먼저 연 뒤 해당 작성창 안의 다중 이미지 첨부칸과 본문을 사용합니다. 검색·이미지 설문·댓글 입력칸에는 넣지 않습니다.

X는 **제목·기사 링크만 있는 첫 글 → 이미지 4장씩 이어지는 댓글** 초안을 버튼 한 번으로 준비합니다. X에서 새 빈 글 작성창을 열고 패널의 `X 제목·링크 + 이미지 댓글 준비`를 누른 뒤, X의 `모두 게시`로 직접 최종 게시합니다. 첫 글에는 이미지를 넣지 않으며, 이미지 댓글에는 본문·크레딧·제목·순번을 반복하지 않습니다. 링크가 없는 원고는 제목만 넣습니다. 기사 URL은 원고 본문에서도 추출합니다. 첫 글은 공식 가중 길이 기준 280자 안이어야 하며, 너무 긴 제목은 오류로 안내하고 임의로 자르지 않습니다.

이미 게시한 글의 빈 답글·인용 작성창을 열었다면 현재 작성창의 원문 표시를 확인하고 **이미지만** 넣습니다(최대 4장). 4장 초과는 일부만 넣지 않고 새 글 작성창에서 전체 흐름을 준비하도록 안내합니다. 새 글 흐름의 준비 범위는 원본 최대 80개/이미지 댓글 20개 + 첫 글 1개이며 X 정책상 최대치를 뜻하지 않습니다. 모든 댓글은 순서대로 연결되는 스레드입니다. 이미 작성 중인 글·사진을 덮어쓰거나, 게시·예약·초안 저장을 자동 클릭하지 않습니다. 중간 실패 시 초안을 유지하고 다음 기사로 넘어가지 않습니다. 원본을 합성·축소하거나 일부를 빼지 않습니다.

일반 YouTube의 커뮤니티 게시물 화면에서는 이미지 최대 10장(JPG·PNG·GIF·WebP, 각 16MB 이하)을, YouTube Studio에서는 영상 1개를 전달합니다. Instagram은 원본 비율 선택을 추가로 시도합니다. 각 사이트 정책이나 화면 개편으로 파일 입력을 받지 않는 경우에도 제목/본문 복사와 순차 이미지 복사는 계속 사용할 수 있습니다.

2.2부터 고대신문 로고를 누르면 관리자 페이지가 열립니다. SNS 탭에 업데이트된 연결 코드가 없으면 패널 전체에 새로고침 안내가 표시됩니다. 버튼을 누르면 현재 SNS 탭만 새로고침하고 패널 상태와 배포 링크는 유지합니다. 복사·전달 상태는 패널 안에만 표시하며 웹페이지 위의 팝업 알림은 사용하지 않습니다. 2.2.1부터 이전 글·다음 글 이동 바는 스크롤 위치와 관계없이 패널 하단에 고정됩니다. 2.2.2부터 제목을 제외한 본문만 복사할 수 있습니다.

패널의 공식 영문 명칭은 `The Korea University Weekly`이며, 포함된 Pretendard Variable 웹폰트를 사용합니다.

## 보안 및 데이터 경계

- 요청 권한: 세션 저장소, 오른쪽 패널, 클립보드 쓰기, 여섯 SNS와 고대신문 Supabase 호스트
- 사용하지 않는 권한: `downloads`, `cookies`, `history`, `webRequest`, `<all_urls>`
- 배포 링크·현재 글 번호·작업 상태는 Chrome 세션에서만 보관하고, 브라우저 종료 뒤 유지하지 않음
- 원본 바이너리는 디스크·Chrome 저장소·Base64에 남기지 않고 RAM에서만 처리
- SNS 로그인 정보나 쿠키에 접근하지 않으며 최종 게시 버튼을 자동으로 누르지 않음

```text
content/site-upload.js        Facebook·고파스·에타·X·YouTube 입력

```
